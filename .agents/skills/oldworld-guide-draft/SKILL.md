# Черновики руководств Old World

Навык применяется к этому репозиторию. Работай от корня, определённого по `AGENTS.md`, `data/achievements.json` и `docs/steam-guides`. Сначала прочитай действующие инструкции проекта. Перед правками кратко предложи состав работы; не превращай это в обязательное ожидание подтверждения.

## Определить тему и охват

- Прочитай `docs/steam-guides/steam-guides-structure.md`, README серии и существующие `<slug>-draft.md`, `<slug>-review.md`, `<slug>-coverage.json` нужной темы.
- При просьбе продолжить следующую тему проверь, что реально подготовлено в `steam-ready`, и используй порядок серии. Если есть несколько одинаково вероятных вариантов, уточни тему; не заменяй выбранную пользователем.
- Возьми точные ID из плана и сопоставь с JSON карточек. Число достижений выводи из данных, не храни устаревающий общий счёт как константу навыка. Не дедуплицируй записи по одинаковым русским названиям.
- Сохраняй уже согласованный материал, порядок и границы темы. Не затрагивай отложенные игровые проверки других руководств.

## Проверка содержания

Карточка с `guideVerified: true`, текст Steam и старый черновик не являются доказательством конкретной тактики.

Для стандартных условий используй XML установленной игры; для скрытых ограничений проследи код выдачи достижения. Обычная папка Reference — `C:/Program Files (x86)/Steam/steamapps/common/Old World/Reference`; если её нет, найди установку или честно укажи отсутствие доступа. Не выдавай недоступную проверку за выполненную.

Проверяй по смыслу задачи:

- Связь Steam API ID с реальным источником выдачи; необходимые DLC по фактическому контенту, а не только по группировке Steam.
- Требуется основание, распространение, создание, владение, событие или победа; когда запускается проверка.
- Одновременно или накопительно; один город или вся держава/мир; живые персонажи или статистика; точное значение или нижняя граница.
- Для событий — исходные фильтры, отношения участников, варианты ответа, продолжение цепочки и бонус выдачи. Не выводи условия из одного названия или краткого описания.
- Для чисел — базовая или фактическая цена, ходы или годы, масштаб времени. Не называй внутренние фильтры персонажей самостоятельными чертами без чтения их определения.

Используй `scripts/inspect-oldworld-xml.py` для выборки записей XML, когда он подходит. Он только читает данные; это не симулятор игры. Смотри также переопределения и дополнительные XML, относящиеся к теме. Для публичных названий и условий сверяй официальный список Steam; при недоступности сайта отметь дату и происхождение имеющейся копии.

Термины бери из русской локализации игры по `AGENTS.md`. Сохраняй официальные названия и условия достижений Steam, а различия с механикой объясняй в пояснении. Не переводи внутренние ID буквально.

Различай три основания: проверено по коду/XML; подтверждено конкретной игровой попыткой пользователя; предположение для проверки. Скриншот и отметка получения не подтверждают автоматически все советы карточки. Если несколько условий не проверены, оставь конкретные вопросы в review и честный статус черновика.

## Результат

Поддерживай существующий комплект темы:

- `<slug>-draft.md`: название, дата и реальный охват проверки, ссылка на каталог, краткое введение/общие правила, тематические разделы, источники. Внутри достижения — заголовок, `**Условие:**`, пояснение, `**Совет:**`. Не добавляй «Steam» к подписи условия. Для связи с данными можно использовать `<!-- achievement: aNNN -->`.
- `<slug>-review.md`: источники и build установленной игры, исправления, оставшиеся вопросы, границы практической проверки. Не отмечай всё проверенным после простого переноса базы.
- `<slug>-coverage.json`: `{"count": N, "ids": [...]}`; точные ID без пропусков и дублей.
- Ссылка и актуальный статус темы в README серии.

Дата последней проверки меняется после содержательной сверки, а не при переоформлении. Не копируй в публичный текст служебный рассказ о ходе работы. При использовании структуры как образца не наследуй её предметные числа и неподтверждённые утверждения.

## Согласование с карточками

При обнаружении расхождений явно перечисли их. Если синхронизация входит в запрос или уже разрешена в текущей работе, перенеси проверенные исправления в `data/achievements.json` и `data/achievements.js`, включая английские пояснения, советы и относящиеся к правке поля редактора/DLC. Если пользователь просит только текст, не расширяй задание на карточки молча.

- Сохраняй ID, официальные названия, прогресс и смысл `playerCivs` (строгое требование) против `affinityCivs` (мягкая связь).
- Не добавляй общее правило Hotseat в отдельные карточки: оно находится во введении гайда и предназначено для будущего «Справочника» приложения.
- Не оставляй в соседнем поле карточки старое противоречащее пояснение. Не меняй остальные карточки ради переформатирования.
- После синхронизации выполни `node scripts/validate-english-achievements.js` и `node scripts/validate-localization.js`; проверь совпадение JSON/JS, список реально изменённых ID и отсутствие правок вне охвата.
- Дай пользователю список изменённых карточек с названиями, ID и сутью изменений. Для подробной проверки используй принятый образец `religion-development-card-changes.md` и машинное сравнение до/после, когда объём это оправдывает.

## Завершение этапа

Сверь охват с планом и данными; проверь все ссылки на созданные файлы. В ответе дай ссылку на черновик, статус проверки и только действительно нерешённые вопросы. Черновик сам по себе не означает создание Steam-файлов, обложки или публикацию. При запросе подготовки к Steam переходи к отдельному навыку `oldworld-steam-files`.
