# Файлы руководства Old World для Steam

Работай от корня репозитория. Прочитай `AGENTS.md`, исходный `<slug>-draft.md`, `<slug>-review.md`, `<slug>-coverage.json` и существующую папку `docs/steam-guides/steam-ready/<slug>-ru`. Перед изменениями сообщи, какие файлы подготовишь. Сохраняй выбранный язык и тему.

## Готовность исходника

- Используй проверенный текст как единственный источник содержимого. Не переписывай советы и стиль при каждом переносе.
- Если пользователь просит также «все проверки», сначала выполни содержательную проверку через навык `oldworld-guide-draft`. При запросе только форматирования не запускай незапрошенный аудит всего каталога.
- Для недопроверенных условий сохрани явную оговорку. Если они меняют рекомендуемый путь прохождения, назови конкретный вопрос пользователю; независимо подготовь части, которые от ответа не зависят. Не объявляй материал полностью проверенным.
- Сверяй фактические файлы: старое наличие `steam-ready` не доказывает ни проверку механик, ни публикацию.

## Единый формат серии

Используй текущие файлы серии как образец оформления. Стабильные подписи: `[b]Условие:[/b]` и `[b]Совет:[/b]`, без слова «Steam» после «Условие».

```text
[h2]Название достижения[/h2]
[b]Условие:[/b] Официальное условие.
Пояснение с нужными ограничениями.
[b]Совет:[/b] Практический способ.

[h2]Следующее достижение[/h2]
...
```

Название раздела вводится в Steam отдельно, не дублируй его крупным заголовком в начале каждого TXT. Названия достижений — подзаголовки h2. Внутри записи строки идут подряд; между достижениями — одна пустая строка. Не меняй русские игровые термины на буквальный перевод английских имён. Сохраняй дату содержательной проверки, ссылку на каталог и существенные оговорки.

Переводи Markdown в BBCode: жирный текст, подзаголовки, ссылки и необходимые списки. Удали служебные ID, HTML-комментарии и Markdown-разметку из TXT; ID сохраняются в manifest, а не показываются читателю. Вспомогательные заметки и внутренние пути оставляй в README/review.

Рабочий бюджет серии — **до 6000 символов и 6000 байт UTF-8 на раздел**, включая разметку и переводы строк. Это редакторский запас, не подтверждённый лимит Steam. Делить можно только между целыми достижениями или самостоятельными вводными абзацами. При необычно длинной записи сначала убери повторы, сохранив условия; не разрывай достижение и не теряй оговорки ради лимита.

## Папка результата

Подготовь `docs/steam-guides/steam-ready/<slug>-ru/` с:

- пронумерованными TXT-файлами для разделов; суффиксы частей добавляй только при нужном разбиении;
- `README.md`: название, краткое описание, порядок переноса, таблица «название раздела → файл», размеры, статус проверки, реальные ограничения;
- `manifest.json`: дата, число достижений и разделы с `file`, `title`, `ids`, `characters`, `utf8Bytes`, `sha256`;
- `preview.html`: локальный просмотр текста и разделов. Обозначь, что это не точный рендерер Steam;
- ссылкой на существующую обложку или её копией `cover.jpg`, если она уже подготовлена. Не генерируй новую обложку без запроса; если запрошена, используй imagegen и стиль `docs/steam-guides/covers`.

**Передавай папку с файлами. Не создавай и не пересобирай архив без прямого запроса.** Не оставляй в актуальном README ссылки на архив со старой версией текста. Старые пользовательские файлы и обложки сохраняй; не удаляй лишние файлы вслепую.

Сохраняй UTF-8 без BOM и LF. Размеры и хеши вычисляй по итоговым байтам на диске, а не только по строкам до записи: Windows может преобразовать LF в CRLF.

## Сборка и проверки

Для повторной подготовки используй существующий генератор темы, если он действительно относится к ней. `scripts/prepare-religion-development-steam.py` предназначен только для руководства о религии и развитии: не запускай его для другого руководства и не подменяй его входные пути. Для новой темы адаптируй подход или создай отдельный небольшой генератор, если он окупается повторной сборкой.

Запусти общий валидатор этого навыка из корня:

```powershell
python .agents/skills/oldworld-steam-files/scripts/check_steam_files.py docs/steam-guides/steam-ready/<slug>-ru --coverage docs/steam-guides/<slug>-coverage.json
```

Он проверяет охват ID, совпадение TXT с manifest, ограничения размеров, кодировку, LF, контрольные суммы и BBCode. Это не проверка фактических игровых условий. Для существующего комплекта без manifest сначала составь его по действительному источнику: не выдумывай ID по названиям, поскольку названия могут дублироваться.

Кроме автоматической проверки:

- Сопоставь подписи, порядок и существенные оговорки с исходником. После проверки механик перенос не должен изменять смысл.
- Проверь локальные ссылки и визуально посмотри вводный и длинный разделы в локальном предпросмотре.
- При исправлении содержимого меняй исходник и пересобирай производные TXT, preview, README и manifest; не правь только HTML или только одну копию.
- Если карточки синхронизировались в рамках этой работы, проверь RU/EN и совпадение JSON/JS штатными проверками проекта. Не добавляй им правило Hotseat.
- Не выдавай локальный просмотр за проверку встроенного редактора Steam. Публикация требует отдельного явного запроса; подготовка файлов её не разрешает.

В ответе дай ссылку на папку и README, количество достижений/разделов, результат проверок и материальные оставшиеся вопросы. Не заявляй о готовой обложке, публикации или игровом тестировании, если этого не было.
