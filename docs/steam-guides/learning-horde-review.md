# Обучение и «Орда варваров»: основания проверки

Последняя проверка: 26 ноября 2026 года. [Черновик](learning-horde-draft.md). Статус: все 12 достижений сверены по источникам выдачи; новое прохождение в игре не выполнялось. Остаётся вопрос распределения совместного зачёта по слотам Hotseat.

## Охват и источники

Это тема № 8 после подготовленного комплекта «Религия и развитие державы». Фактически просмотрены каталоги `steam-ready`: characters-ru, cognomens-ru, religion-development-ru и wonders-ru. Другие существующие черновики не переоткрывались для исправления механик.

Охват взят из раздела 8 `steam-guides-structure.md`: 5 коротких учебных миссий, 4 учебные партии и 3 достижения Орды. [Coverage](learning-horde-coverage.json) содержит точные ID в порядке плана; одинаковые начала названий не объединялись.

Установленная игра: `C:/Program Files (x86)/Steam/steamapps/common/Old World`, Steam build **26728102** по `appmanifest_597180.acf`. [Аудит источников](learning-horde-audit.json) сохраняет связи API ID с выдающими записями, отметки авторского экспорта и SHA-256 файлов игры. В число хешей входят также сопутствующие XML и исходники модулей; хеш файла сам по себе не означает проверки каждой его строки.

[Русский список Steam](https://steamcommunity.com/stats/597180/achievements/?l=russian) получен 26 ноября 2026 года: 408 записей, все 12 нужных API ID найдены. [Снимок нужных названий и условий](learning-horde-steam-check.json) сохранён отдельно. Обычный запрос с `l=russian` вернул английский текст; русский ответ получен с cookie `Steam_Language=russian` и заголовком `Accept-Language: ru-RU`. Проверялась фактическая локализация ответа, а не только параметр URL. Четыре русских названия и условия учебных партий отличаются от базы неразрывным пробелом перед тире; в черновике сохранён текст ответа Steam.

Для основной выборки использован `scripts/inspect-oldworld-xml.py` по `achievement`, `scenario`, `subject`, `difficultyMode` и `text-infos`. Дополнительные сценарные XML просмотрены отдельно. Игра не изменялась. После подготовки черновика по запросу автора синхронизированы пять карточек; [список и сравнение](learning-horde-card-changes.md).

## Короткое обучение — a128, a127, a126, a125, a124

`scenario.xml` связывает каждое достижение с отдельным сценарием `SCENARIO_LEARNTOPLAY_1` — `_5`, модулем `LearnToPlay1` — `LearnToPlay5` и Грецией. В локализации группа называется **«Учимся играть»**, а миссии — **«Обучение 1»** — **«Обучение 5»** с подзаголовками «Старый мир», «Место для жизни», «У всех есть свое мнение», «Корона тяжела», «Полемос».

Прямые записи выдачи в `Infos/bonus-event-add.xml` соответствующих модулей:

| ID | Бонус |
|---|---|
| a128 | `BONUS_EVENTOPTION_LEARNTOPLAY1_9` |
| a127 | `BONUS_EVENTOPTION_LEARNTOPLAY2_VICTORY` |
| a126 | `BONUS_EVENTOPTION_LEARNTOPLAY3_VICTORY` |
| a125 | `BONUS_EVENTOPTION_LEARNTOPLAY4_VICTORY` |
| a124 | `BONUS_EVENTOPTION_LEARNTOPLAY5_VICTORY`, `BONUS_EVENTOPTION_LEARNTOPLAY5_EARLY_OUT` |

Для этих бонусов прослежены ссылки из вариантов ответа и событий в том же модуле. `LearnToPlayNGame.isValidAchievement` дополнительно ограничивает выдачу единственным учебным достижением своей миссии. Общая проверка `Game.isValidAchievement` продолжает действовать.

Особенность a124: `LearnToPlay5Player.doTurn` во время активного завершающего завоевания вызывает `EVENTTRIGGER_GOAL_LEARNTOPLAY5_EARLY_OUT`, если у проверяемого нечеловеческого игрока осталось меньше двух городов. Событие `EVENTSTORY_LEARNTOPLAY5_EARLY_OUT` предлагает завершить обучение либо продолжить. Первый вариант вызывает бонус с `Victory=VICTORY_CONQUEST` и самим достижением. `LearnToPlay5Game.makeWinner` заменяет вид победы на `VICTORY_AMBITION`; обычное победное событие тоже имеет выдающий бонус. Таким образом, полное уничтожение Рима не обязательно. Это вывод по коду и цепочке XML; новый игровой тест этого варианта не проводился.

## Учебные партии — a054, a212, a246, a258

В `scenario.xml` используются `SCENARIO_LBP_ABLE`, `_JUST`, `_GOOD`, `_STRONG` и группа `SCENARIOCLASS_LBP`, локализованная как **«Учебные партии»**. Это отдельные фиксированные партии, а не дополнительные условия первых четырёх коротких миссий.

| ID | Цивилизация | Подзаголовок в игре | Набор настроек |
|---|---|---|---|
| a054 | Вавилония | Вавилония Способная | Способный |
| a212 | Египет | Египет Справедливый | Справедливый |
| a246 | Персия | Персия Добрая | Добрый |
| a258 | Рим | Рим Могучий | Могучий |

`Game.makeWinner` перебирает `scenario.maeAchievements` для игроков победившей команды и вызывает `doAchievement`. Требование конкретного вида победы у этих четырёх записей отсутствует. Каждый модуль LearnByPlaying объявлен одиночным сценарием; карты находятся в его папке Maps. Дополнения в данных этих стандартных сценариев не требуются.

У Египта `Difficulty=DIFFICULTY_GOOD` не означает автоматически набор «Добрый»: `difficultyMode.xml` различает «Справедливый» и «Добрый» через развитие соперников, их преимущество и прочие параметры. У Египта проверены `Development=DEVELOPMENT_NONE`, `Advantage=ADVANTAGE_PENALTY_SMALL`; у Персии — `DEVELOPMENT_FLEDGLING` и `ADVANTAGE_NONE`. Внутренний ID одного параметра не переводился как название всего набора.

## Орда — a353, a316, a250

Источники: `Source/Mods/Barbarian/BarbarianGame.cs`, XML модуля Barbarian (`eventStory-add.xml`, `bonus-event-add.xml`, `uprisingTime.xml`, параметры сложности и организации), `subject.xml`, общие `Game.makeWinner` и `Game.isValidAchievement`.

- `startBarbarianInvasion` создаёт Орду, вызывает `setVictoryGoalUnitCount` и отмечает начало вторжения. **`setVictoryGoalUnitCount` устанавливает порог ровно 0.**
- `doVictory` требует начавшееся вторжение, не начальный ход, число налётчиков не выше этого порога и живого человеческого игрока. Если все люди погибли, игра заканчивается без такой победы.
- `getRaiderUnitCountTotal` считает все юниты `Globals.RAIDERS_TRIBE`. Это не счётчик всех племенных юнитов и не счётчик только вновь созданных отрядов.
- a250: скрытое `EVENTSTORY_ACHIEVEMENT_BARBARIAN_INVASION` реагирует на `EVENTTRIGGER_WIN_GAME` с `VICTORY_BARBARIAN_HORDE` и выдаёт `BONUS_BH_VICTORY`.
- a353: такое же победное событие требует `MinTribeLevel=TRIBELEVEL_RAGING` и `MinDifficulty=DIFFICULTY_GREAT`. Это нижние границы. Общая блокировка обычных достижений в Hotseat с несколькими людьми сохраняется.
- a316: есть два пути. Скрытое победное событие использует `SUBJECT_PLAYER_US` и `SUBJECT_PLAYER_SAME_TEAM_HUMAN`; последний требует другого человека в той же команде (`bIsNotUs`, `bIsSameTeam`, `bHuman`). Прямой путь в `BarbarianGame.doVictory` при `!isSinglePlayer()` вызывает достижение для первого живого человека через `getHumanPlayer()` с параметром `!isMultiplayerHotseat()`. Поэтому он обходит Hotseat-блокировку, а обычный бонус события — нет. Само наличие этой ветви не доказывает выдачу всем людям в Hotseat.
- Время подготовки: 60/80/100/120 ходов; случайный вариант `60 + randomNext(61)`. В расчёте числа вторгающихся войск учитывается `getBarbarianScenarioTime() - 100`; долгая подготовка увеличивает размер вторжения. Человеческие и ИИ-участники также увеличивают его. Сравнительная лёгкость вариантов не проверена прохождением.
- Организация племён меняет коэффициенты размещения. Основания обещать, что «Разбросанные» всегда проще, не получено; такой совет не перенесён.

Во время первичного чтения `doVictory` возник вопрос, не допускает ли победа ненулевой остаток Орды. Он закрыт чтением `setVictoryGoalUnitCount`: **нулевой порог подтверждён**, противоречия карточкам здесь нет.

## Практическое подтверждение и нерешённый вопрос

В `practice-evidence.md` по авторскому экспорту от 21 ноября отмечены a128, a127, a126, a125, a124 и a054: **6 из 12**. Это подтверждает отметку получения, но не конкретный выбор в пятой миссии, не всю предложенную тактику и не каждый маршрут. Новых подтверждённых игровых попыток в этой работе нет.

**Нужен игровой тест:** кому именно выдаётся a316 в Hotseat с двумя людьми в одной команде — первому живому слоту либо обоим? Отдельно проверить, что смена активного слота после победы не меняет результат. До такого теста не обещать совместный зачёт всем слотам. Для остальных достижений блокировка многопользовательского Hotseat установлена по общему коду.

Меню и сценарии в этой работе не открывались: русские подписи проверены по локализации, а не по свежим скриншотам. Советы о выборе военной стратегии — рекомендации, не доказанный оптимальный маршрут. Никакие отложенные проверки других тем, включая Александра, не затрагивались.

## Проверка комплекта

- 12 уникальных ID и порядок сверены с разделом 8 плана и карточками.
- Для каждого ID проверены актуальные русские название и условие Steam.
- Для каждого достижения сохранён источник выдачи; для скрытых ограничений прочитаны код и сценарные цепочки.
- В тексте есть «Условие:» и «Совет:» для всех 12 достижений.
- Локальные ссылки и охват проверены автоматически.
- Комплект содержит черновик, review, coverage, снимок Steam и аудит источников. Подготовка файлов Steam, обложка, архив и публикация в этот этап не входят.
